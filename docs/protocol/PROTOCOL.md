# 基准对比协议 v1 草案

每条 Query 固定历史原始结果为 baseline，以 resource_id、原文件 SHA256、Response SHA256、Rubric版本联合标识；不以旧分数作为真值。基准也接受独立绝对评估，可能本身不合格。

输入：固定公开上文、当前指令、同一份冻结 Rubric、基准与候选完整回应及实际产物、各自证据覆盖。裁判不可看模型名、版本名、旧分数和“基准”标签。呈现为 X/Y；第一遍 X=baseline，第二遍 X=candidate，独立调用并留存映射。

输出逐个 Rubric 的比较：X更好/Y更好/等效/证据不足，给实际观察、对应产物及时间码。不得将长度、解释详细程度当作任务效果，不把对缺失文件的文字描述当作产物，不偏好基准身份。必要条件的确定违反另报，质量偏好不能抵消违规。离散验收型条目双方均满足时比较结果为等效，不强造优劣。

换序合并：两次映射回候选后同为赢=100、同为输=0、均等效=50；赢+等效、输+等效或赢输冲突均待仲裁，不平均。任一次缺证据则该项不可比。按预先冻结的比较权重加权，报告共同可比覆盖；不可比不得填50。

合分建议默认绝对结果80%、相对基准20%。绝对分使用独立可观测原子条目，内容效果质量单列；相对分不再重复加同一事实的“改进奖励”。只有绝对评估和相对评估证据满足发布条件、同一预算与合法分支可比时计算 `final=0.8*absolute+0.2*pairwise`；任一必要项确定失败仍显示未通过。未知或待仲裁时提供总分区间与缺失部分，不提供伪精确总分。权重属于工程初始配置，后续用人工偏好样本校准并版本化，不据当前候选调权。

基准自身没有实际新候选时显示“尚未比较”，不把与自身同一文件的相等关系当作真实模型API对比结果。当前28条重评的绝对分不混入虚构pairwise分；新抓取结果接入后才计算双向对比与综合分。

对照实验口径：同一Query同标准、同取证契约、同完成状态；外部人为取消从内容比较准入中分列，但保留交付/中断统计。比较层同时报告赢/输/平/不足/仲裁数量及全部样本分母。仅可比配对胜率必须和覆盖率一起展示。

对比分仅面向来源支持的创作内容任务。对比Rubric由完整context独立生成、质检并冻结，之后才加入两份结果。纯问答/执行任务若无独立创作维度，显示不适用；不强行计审美分。

绝对分的原子计分 v2：保留每个父项原预算，在该父项的适用检查项内均分；每项P得本项分、F得0、U保留区间，N/A退出该父项内部均分。父项任何必要检查失败仍触发未通过，部分得分不能抵消门槛。此规则统一用于所有候选及旧结果的重算，不按当前候选表现调权。未来生成时可事先给原子项显式权重并另行版本化。

覆盖门槛80%是初始发布配置，并非可靠性保证。对比时同时输出共同可比维度与权重掩码；不能把不同缺失集归一化后的分数直接排总榜。综合分存在区间时只给暂定比较；区间重叠不宣称整体胜出。
