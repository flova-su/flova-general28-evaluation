# 固定历史结果的双向对比

基准注册表保存在本地 `local-data/general28-multimodal-v2/baseline-registry.v2.json`，包含28条查询的历史回应、context、验收Rubric和已恢复媒体哈希。基准本身可能失败，不能作为正确答案。

准备顺序：

1. 从完整context生成对比Rubric，独立质检并冻结；使用本目录的生成、质检prompt。不要先看新结果。
2. 按输入schema填入相同任务的baseline/candidate及实际媒体路径、哈希、证据缺口。修改前输入参考要和历史结果baseline分开。
3. 调用 `run.py input.json --out 私有新目录` 只生成AB/BA请求；检查完整context、同一Rubric及左右交换是否正确。
4. 加 `--execute` 才会通过已有Loom helper真实调用两次。凭据仍在helper管理，脚本不保存或输出Key。无自动重试，失败保留原件，目录不覆盖。
5. 两次结论一致后计算比较分。提供绑定新候选ID、Query和验收Rubric哈希的 `absolute_evaluation` 时，同时输出 `composite-score.json`，否则明确等待绝对评估。

每项双向胜100、平50、负0；一次不足即不可比；方向冲突或胜负与平不一致进入仲裁。部分可比时同时给固定100分预算下的区间与覆盖，不能只报已可比项归一化分。

默认合分为绝对分80%、对比分20%，权重待人工样本校准。确定违反必要项依然未通过；区间不取中点，重叠不宣称整体胜出。相同查询多个版本必须使用同一冻结标准和共同可比掩码，不把不同缺失集各自归一化后直接排名。
