Rubric generation v3 supplement (append to the query-specific generator; never show candidate output):
- Compile requirements solely from the full historical context and current request. Provide a version-bound platform factbook/model alias dictionary separately; unknown platform facts are evaluation prerequisites, not guessed user requirements.
- Each C checks one independently provable fact. Separate delivery existence/count from forbidden side effects; separate model identity from output resolution; separate artifact duration from spoken content completeness. A conjunction may remain only when it is a single inseparable acceptance fact.
- Every C declares the acceptance object, P/F/U/N/A anchors, applicability and required evidence channels. Negative constraints define a finite target-turn action scope, trusted closure requirements and disqualifying actions. Do not demand evidence of every conceivable unrecorded action.
- State preservation accepts before/after snapshots or a complete semantically checked mutation set. Specify protected objects/fields. Do not require raw unchanged media for a change that cannot touch them; do require actual media where perception is the acceptance object.
- Required delivery absent with trustworthy terminal evidence is a failure of completion; unavailable evaluator evidence is U. Define dependent quality applicability in advance, so absence does not create accidental score windfalls or multiple penalties. Keep delivery outcome and cancellation attribution separate.
- For explicit visible/audible qualities, define the intended viewing/listening conditions and recognizability anchor. 'Full file available but required feature not recognizable' differs from 'file unavailable'. Do not substitute recipes for observed qualities.
- Specify actual delivery semantics for files: persisted native downloadable document may qualify where supported; do not invent a ZIP/export-job requirement. If actual export completion is requested, state what proves completion/delivery versus merely explaining how the user can export.
- Parent budgets total 100. Assign stable explicit child budgets/fact IDs before candidates arrive; splitting a C must preserve the original fact budget rather than implicitly redistributing sibling weights. Record rubric version and migration; never silently retrofit scoring after viewing candidate outcomes.
- Emit evidence_prerequisites and task_information_gaps separately. Quality risks/preferences must not be promoted to hard constraints. Existing production rubric schema must be migrated explicitly before adding fields; do not claim the future fields were used by an older runner.
